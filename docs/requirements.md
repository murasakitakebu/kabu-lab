# 要件定義書 — Kabu Lab（日本株 戦略研究プラットフォーム）

版：v0.1（2026-10-16）
利用者：オーナー1名（将来的に拡張可能な設計とする）
対象市場：東証上場の日本株（将来、米国株等に拡大）

---

## 1. 目的
1. 過去の値動きから「この時期にここに投資していたら」を検証し、相場感を養う
2. 著名投資家・流行の投資手法を学び、実データでスクリーニング・バックテストする
3. 有報・決算短信の「どこを読むべきか」を手法と銘柄に応じて示し、読む力を鍛える
4. 仮想資金で売買し、自分を運用会社に見立てて規律ある投資判断を練習する

## 2. 機能一覧とフェーズ

| Phase | 機能 | 概要 |
|---|---|---|
| 1 | データ基盤 | J-Quants から銘柄一覧・日足・配当・財務を取得し DuckDB に保存 |
| 1 | タイムマシン計算機 | 銘柄・購入日・金額 → 現在価値、配当込みリターン、指数比較 |
| 2 | 手法ライブラリ | 手法ごとの解説＋スクリーニング条件 |
| 2 | スクリーナー | 任意時点での条件該当銘柄の抽出 |
| 2 | バックテスト | 定期リバランス戦略の過去検証 |
| 3 | 読み方ナビ | EDINET書類から手法別の要注目箇所を抜粋・解説 |
| 4 | ペーパートレード | 仮想資金での売買と損益記録 |
| 4 | 自己資本投資部モード | 投資メモ → AI投資委員会 → 承認後に売買、月次運用報告 |
| 5 | 本格Web化 | FastAPI + Next.js、認証、スマホ対応 |

## 3. Phase 1 詳細

### 3.1 データ基盤
- 取得対象（J-Quants V2）
  - 上場銘柄一覧（市場区分、業種、規模区分）
  - 株価四本値（日足、調整後価格を含む）
  - 財務情報（決算短信ベース：売上、利益、EPS、BPS、配当、予想値、開示日）
  - 指数（TOPIX）
- 要件
  - 初回フル取得スクリプトと日次差分更新スクリプト
  - レートリミットに合わせた自動スロットリングとリトライ
  - 取得ログ（日時、件数、エラー）を保存
- 保存期間：契約プランで取れる最大期間

### 3.2 タイムマシン計算機
- 入力：銘柄（コード／社名検索）、購入日、投資金額、（任意）売却日、配当再投資の有無、NISA有無
- 出力
  - 購入株数（単元考慮あり／なし切替）、評価額、損益、トータルリターン、年率（CAGR）
  - 期間中の最大ドローダウン
  - 受取配当の累計
  - TOPIX・定期預金との比較チャート
- 応用
  - 積立モード：毎月◯円を買い続けていたら（ドルコスト平均法）
  - 複数銘柄の同時比較（最大5銘柄）
  - 「ランキング」：指定期間に最も上がった／下がった銘柄TOP20

### 3.3 Phase 1 タスク
1. リポジトリ雛形作成（uv、ruff、pytest、.env.example、.gitignore）
2. `core/data/jquants.py`：APIクライアントのラッパー（スロットリング・リトライ）
3. `core/data/store.py`：DuckDB スキーマ定義と upsert
4. `scripts/initial_load.py`／`scripts/daily_update.py`
5. `core/calc/returns.py`：一括投資・積立のリターン計算（分割・配当調整、税金）
6. 上記のユニットテスト（分割を挟むケース、配当再投資ケース、NISAケース）
7. `app/pages/1_タイムマシン.py`：Streamlit UI
8. 動作確認：トヨタ（7203）、任天堂（7974）などで既知の値と突き合わせ

## 4. Phase 2：手法ライブラリ・スクリーナー・バックテスト

### 4.1 手法テンプレート
各手法は以下をセットで定義する。
- 名前、提唱者、考え方の要約（300字程度）
- スクリーニング条件（パラメータ化）
- リバランス頻度の推奨
- 読み方ナビで重点的に見る開示箇所
- 弱点・向かない相場
- 参考文献

### 4.2 初期に実装する手法
| 手法 | 主な条件（例・パラメータで調整） |
|---|---|
| バフェット流（クオリティ） | ROE 10年平均 ≥15%、営業利益の安定性、低負債、適正価格 |
| グレアム（ネットネット） | 時価総額 < 流動資産 − 総負債 |
| グリーンブラット（魔法の公式） | 益回り × 資本収益率の合成順位 |
| リンチ（PEG） | PER ÷ EPS成長率 < 1 |
| 高配当・累進配当 | 配当利回り、減配なし年数、配当性向 |
| 東証改革テーマ | PBR < 1、ネットキャッシュ大、政策保有株式・自社株買い余地 |
| モメンタム | 過去12ヶ月リターン（直近1ヶ月除く）上位 |

### 4.3 バックテスト
- 設定：ユニバース（市場区分・時価総額下限・流動性下限）、期間、リバランス頻度、銘柄数、加重方法
- 出力：資産推移、CAGR、最大DD、シャープレシオ、勝率、年別リターン、保有銘柄履歴
- 必須の注意表示：生存バイアス、ルックアヘッド、取引コストの前提

## 5. Phase 3：レポートの読み方ナビ

### 5.1 概要
EDINET から有報・四半期報告書（半期報告書）等を取得し、手法と銘柄に応じて
「ここを読め」を示す。読み方の学習ツールであり、投資推奨ではない。

### 5.2 読むべき箇所マップ（初期版）
| 書類・箇所 | 何がわかるか | 特に重要な手法 |
|---|---|---|
| 決算短信 1ページ目サマリー | 業績・予想・進捗率 | 全般 |
| 業績予想の修正理由 | 上振れ／下振れの要因 | モメンタム、成長 |
| 事業の内容 | ビジネスモデル | バフェット |
| 事業等のリスク | 経営陣が認識するリスク | 全般 |
| 経営者による分析（MD&A） | 課題認識と戦略 | バフェット、リンチ |
| セグメント情報 | どの事業が稼いでいるか | バフェット、リンチ |
| キャッシュフロー計算書 | 利益の質（営業CF vs 純利益） | 全般 |
| 貸借対照表（流動資産・負債） | 清算価値 | グレアム、東証改革 |
| 大株主の状況 | 持ち合い、アクティビスト | 東証改革 |
| 政策保有株式（コーポレート・ガバナンスの状況） | 売却余地、資本効率 | 東証改革 |
| 配当政策・資本政策 | 還元方針 | 高配当 |
| 注記（継続企業の前提、偶発債務、関連当事者取引） | 赤信号の有無 | 全般（DD視点） |

### 5.3 機能
- 該当箇所の抜粋表示（原文へのリンク付き）
- Claude API による解説：「この会社のこの数字はこう読む」「前年からの変化」
- 赤信号チェックリスト（営業CF赤字継続、継続企業注記、監査人交代など）
- 学習ログ：読んだ箇所とメモを記録

## 6. Phase 4：ペーパートレード／自己資本投資部モード
- 仮想資金（デフォルト1,000万円）、約定は翌営業日始値（または当日終値）
- 取引履歴、保有一覧、NAV推移、TOPIX比較
- 売買時に「投資理由」の入力を必須化
- 自己資本投資部モード
  - 投資メモ（テーゼ、カタリスト、リスク、撤退条件）を作成
  - AI投資委員会が反論・質問 → 回答後に承認して売買
  - 月次運用報告書を自動生成
- 振り返り：理由と結果を比較し、自分の傾向（損切り遅れ等）を可視化

## 7. 非機能要件
- 個人利用のためローカル実行で可（Phase 5 までは認証不要）
- APIキーは `.env` 管理、リポジトリに含めない
- J-Quants・EDINET の利用規約を順守（データの再配布をしない）
- 本ツールの出力は学習・検証目的であり、投資助言ではない旨を画面に表示

## 8. 前提・確認事項
- J-Quants はプランにより取得可能期間・レートリミットが異なる（V2 では Free 5、Light 60、Standard 120、Premium 500 req/分）。
  バックテスト用途では長期間データが必要なため、プラン選択を Phase 1 開始前に決める
- **決定（2026-11-11）：J-Quants は Free プランで開始**
  - 取得範囲：直近12週間を除く過去2年分。5 req/分
  - 取得可：上場銘柄一覧、株価四本値（日通し）、バリュエーション指標、財務情報サマリー、決算発表予定日、取引カレンダー
  - 取得不可：TOPIX四本値（Light〜）、指数四本値（Standard〜）、配当金情報（Premium のみ）
  - 代替：TOPIX・日経平均は連動ETF（1306・1321）の株価で近似する。配当は財務サマリーの
    1株配当（中間・期末の実績）と決算期末日（≒権利確定日）から推定する。どちらも結果画面に近似である旨を表示する
  - 有料プランへ移行したら、本来のデータ（TOPIX四本値・配当金情報）に差し替える
- 上場廃止銘柄のデータ取得可否を確認する（生存バイアス対策）
- EDINET API の Subscription Key を事前に取得する
